## 2. The product
- **Bee There** — travel map web app: pin places you have been, save check-in memories with photos, plan group trips (itinerary, costs with settle-up, checklist), guides and country tips, social features (follow, likes, share).
- Live: **https://beetheremap.com** (GitHub Pages, custom domain via `CNAME`).
- Repo: **huynhthu1704/travel-map** (personal repo, default branch `main`).
- Stack: React 18 + Vite 5, Firebase on the free **Spark** plan (Auth + Firestore; project `travel-map-e9657`). No server code, no Cloud Functions. Demo mode (no Firebase keys) stores data in localStorage.
- Design: honey-yellow design system (Figma). Bilingual UI: VI (default) + EN, strings in `src/i18n.jsx` and `src/i18n-en.js`.

## 3. Delivery contract (AGENTS.md / Compass)
- Every change has a **REQ** (Given/When/Then acceptance criteria) and at least one **TC** in `compass/spec.json`; `node compass/check-spec.mjs` must pass. `compass/requirements.md`, `compass/tests.md`, `compass/handover.md` and `compass/decisions.md` are generated views of the spec: after editing `spec.json` run `node compass/build-views.mjs` (REQ-047); `check-spec` fails in CI when `handover.md` is stale (open requirements, their status, counts or feature rows differ). If a Compass portal push turns CI on main red for this reason (check-spec and also `npm test`, which compares requirements.md, tests.md and decisions.md with the generator), run `node compass/build-views.mjs` and merge the regenerated files in a small PR.
- spec.json v2 (portal format): `features` (F-001…), requirements with `story`, `featureId`, `ac` as strings `"Given…\nWhen…\nThen…"`. Baseline of the existing product = REQ-101…153 (TC-101…).
- Branch `compass/REQ-xxx-short-name`; **≤ 12 files per change**; CI green before merge (squash merge).
- **Protected paths — never change without explicit approval:** `.github/workflows/`, `compass/guardrails.json`, the enforcement files (`compass/check-guardrails.mjs`, `compass/guardrails-lib.mjs`, `compass/hooks/`, `.claude/settings.json`, `.claude/settings.local.json`, REQ-050), `.env`, `CNAME`. Never commit secrets or `.env`.
- **Guardrails are enforced (REQ-036):** the edit hook blocks protected/forbidden paths and secrets (approval route: Christine approves in chat → add the path to `.claude/approved-paths.local.json`); the CI *Guardrails check* runs main's copy of the check and its rules (REQ-050, so a PR cannot weaken the check that judges it) and fails PRs over 12 files, with forbidden paths, secrets, or — without the `human-approved` label — protected paths, deletions or dependency changes.
- **Never force push** (use a new branch name such as `-v2` instead). Deleting files needs Christine's OK.
- The Compass portal sometimes commits straight to `main` and can overwrite `compass/spec.json` — merge by requirement id instead of taking one side.

## 6. Tests and CI/CD
- Unit tests: `npm test` (node:test, `tests/*.test.mjs`).
- UI tests: Playwright, `npm run test:e2e` (`e2e/*.spec.mjs`, projects `desktop` and `phone`). `e2e/fixtures.mjs` seeds demo data (trips t1 Singapore & Malaysia, t2 Kyoto, t3 Bali with code BALI2027), blocks external requests, auto-accepts confirm dialogs; helper `openApp(page, path, {flags, role, lang, tour, newUser, …})`.
- **Compass CI** (`compass-ci.yml`): spec check, `npm audit` (fails only on *critical* in shipped libraries; full report in run summary), unit tests, build, Playwright; nightly run 03:00 VN time; Playwright report kept as a run artifact (Actions → run → Summary → Artifacts).
- **Compass Deploy** (`compass-deploy.yml`, REQ-034): runs only after Compass CI is green for a push to `main`, deploys that exact commit, smoke-tests the live site (title + new hashed script) and on failure redeploys the last good version and opens a `bug` issue. Automatic deploys skip any commit that is not the newest commit of `main` (REQ-058, after CI runs finished out of order on 2026-11-26); manual deploys/rollbacks are never skipped. Manual rollback: Actions → Compass Deploy → Run workflow → commit SHA.
