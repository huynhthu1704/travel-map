## Approach
REQ-002 is a cross-cutting baseline, so it gets no new page. The design adds three things on top of the existing app. (1) A shared focus and keyboard layer on the existing shell, pages and `Modal`. (2) A fast-start Home page that reuses the lazy-loading approach already in REQ-011. (3) The F-001 'Add suggestion to checklist' dialog, built to the baseline so TC-003 and TC-004 can be checked on a real form. It reuses `Modal`, `Combobox`, the `.btn` and `.field` styles and the toast via `notify`. Page CSS stays split per page (`src/styles/pages/`) [S4 agent-knowledge]. Nothing new is added to the first load.

### SCR-1 · Keyboard and focus baseline (all pages)
**Elements:** 'Skip to main content' link, the first tab stop on every page, visible only on focus; Landmarks: header/nav, main, and the bottom nav on phones labelled with aria-label; One global :focus-visible style with a high-contrast ring (at least 3:1 against the background) on buttons, links, icon-buttons, inputs and the Combobox. No outline:none without a replacement; Icon-only controls (✕, ✏️, 🗑️, 📅) keep an aria-label. Fix any that lack one, e.g. the Combobox clear button has a hard-coded 'Clear'. Use t() instead; Logical tab order that follows reading order. Custom clickable divs become real <button>/<a> or get role, tabIndex and Enter/Space handlers; Existing Modal: keeps role=dialog, aria-modal and Escape to close. Add focus moved into the dialog on open, focus kept inside while open, and focus returned to the trigger on close. This was not visible in the code read; Status messages (toasts) use role=status / aria-live=polite. Errors use role=alert; Colour is never the only signal. The due-today (yellow) and overdue (red) checklist states also carry text or an icon

**States:** Default: no visible ring on mouse clicks, ring on keyboard focus; Focused: visible ring on every control; Modal open: focus trapped, Escape closes, focus returns to the opener; Error: message linked to its field with aria-describedby and announced; Reduced motion: transitions and animations are off when prefers-reduced-motion is set

### SCR-2 · Home page fast start (4G)
**Elements:** Reuse the REQ-011 lazy loading: map libraries, country borders, the English dictionary and heavy studios are loaded only when needed; Non-blocking CSS, split per page, and a small critical shell that paints first; Images with width/height set and lazy loading below the fold, so layout does not shift; Skeleton or Loader (existing ui Loader) for content that arrives late, with aria-busy on the region; The 'Add to checklist' code from F-001 is lazy-loaded with the Guides page or dialog, not in the home bundle; The performance check is a Lighthouse mobile 4G run on the home page with Time to Interactive/TBT under budget

**States:** Loading: shell and skeleton shown, controls already focusable; Loaded: interactive within 2.5 s; Slow or offline network: content that did not load shows a short message with a Retry button, and the rest of the page still works; Error: a failed lazy chunk shows a retry message instead of a blank screen

### SCR-3 · Add suggestion to checklist dialog (F-001, built to the baseline)
**Elements:** Opened from an 'Add to checklist' button on each Guide suggestion, a real <button> with an accessible name that includes the suggestion text; Existing Modal with title 'Add to checklist'; Read-only line showing the suggestion text; Trip selector: existing Combobox, with a visible <label>, role=combobox, and arrow/Enter/Escape keys; Primary button 'Add' and secondary 'Cancel', with the existing .btn styles. Enter submits; Inline error text under the trip field, red and with an icon, with role=alert and linked by aria-describedby; Toast on success through notify(), announced by a screen reader

**States:** Default: focus lands on the trip selector. If the user has only one trip it is preselected and focus goes to 'Add'; Empty: the user has no trips. The dialog explains this and offers 'Create a trip', and Add is not offered; Invalid input: no trip chosen. Show 'Choose a trip first', keep focus on the trip field, save nothing; Loading: while saving, the existing Loader replaces the buttons and the dialog stays open; Success: confirmation toast and the dialog closes. Focus returns to the 'Add to checklist' button; Error: saving failed or offline. Show 'Could not add this item. Try again' in the dialog, nothing is saved, and the user can retry; Duplicate: the item is already on that checklist. Show a message and do not add it twice

## Notes
Accessibility:
- Target is WCAG 2.1 AA: text contrast 4.5:1, focus ring and icon contrast 3:1, touch targets at least 44x44 px on phones.
- Texts must exist in both VI and EN (`src/i18n.jsx`, `src/i18n-en.js`). Check that the aria-labels and error messages are translated, not hard-coded.
- Automated check for TC-003: a keyboard-only Tab walk through each page, plus an axe scan. TC-004 is manual: submit the dialog with no trip chosen and confirm the error and that nothing is saved.

Responsive (phone):
- The dialog uses the existing Modal, with `modal--sm` on narrow screens. The controls stack full-width.
- The bottom nav must not cover the focused field. Scroll the focused element into view.
- The virtual keyboard must not hide the error or the Add button.
- The skip link and focus ring must also work with an external keyboard on a tablet.

Open questions:
1. Is the 2.5 s target for the home page only, or also for Guides? The requirement says home page only.
2. Should the 'Add to checklist' button show only to signed-in users? Per the FAQ, creating trips needs a Google sign-in.
3. The Combobox and Modal are read only in part (snippets). Confirm which focus-trap and focus-return behaviour already exists before changing them.
4. The ideas notes say 'increase the number of user' is unclear (more app users or more trip members). The Product Owner should confirm. This does not change the REQ-002 screens.
5. The dialog and the Guides button come from other F-001 requirements. They are shown here only to apply REQ-002 and need to be linked to those requirements' own screens.
