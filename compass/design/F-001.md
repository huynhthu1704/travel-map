## Approach
The design adds one new action to the Guides page, one dialog, and one panel in the existing Admin → Insights. It adds a baseline for every page and a fast Home page. It reuses what the repo already has: `Modal`, `Combobox`, `.btn` and `.field` styles, the `notify` toast, the `Loader` in `ui.jsx`, the `can('<key>')` feature flags in `src/data/flags.js`, and the `insights` permission in `src/lib/roles.js`. The new UI goes behind a flag with `defaultOn: false`, as the agent-knowledge notes require. The checklist item limit is `CHECK_ITEM_MAX` = 120 in `src/lib/checklist.js`. The 'Add to checklist' code loads with the Guides page, so the Home bundle does not grow. I did not read `Modals.jsx`, `Combobox.jsx`, the Guides UI or the Admin Insights UI. Their exact current behaviour (focus trap, focus return, Combobox ARIA, Insights layout) is still to be confirmed.

## Notes
Accessibility (WCAG 2.1 AA):
- Text contrast is 4.5:1. Focus ring and icon contrast is 3:1. Touch targets are at least 44x44 px on phones.
- Errors use role=alert and are linked to their field with aria-describedby. Toasts use role=status.
- Every new string exists in VI and EN (`src/i18n.jsx`, `src/i18n-en.js`), including aria-labels and error messages.
- The Insights table uses real headers. The period control works with arrow keys.
- Tests: TC-003 is a keyboard Tab walk plus an axe scan on each page, including Guides, the dialog and Insights. TC-004 is manual: open the dialog, submit with no trip chosen, and confirm the error and that nothing is saved.

Responsive (phone):
- The dialog uses `modal--sm` and the controls stack full-width.
- The bottom nav must not cover the focused field. Scroll the focused element into view.
- The virtual keyboard must not hide the error or the Add button.
- The Insights table scrolls horizontally, or turns into a stacked list on narrow screens.
- The skip link and focus ring must also work with an external keyboard on a tablet.

Open questions:
1. Is the 2.5 s target for the Home page only, or also for Guides? REQ-002 says Home only.
2. Should 'Add to checklist' show only to signed-in users? Creating trips needs a Google sign-in. A signed-out user is sent to sign-in.
3. Which focus-trap and focus-return behaviour does `Modal` already have? It must be confirmed before changing it.
4. Which Guide data has a stable id for each suggestion? REQ-005 needs a suggestion id stored on the item, so a renamed item is still a duplicate. This changes the checklist item shape.
5. How are counts stored, and who can write them? The data must hold only Guide, date and count (REQ-008), so the Firestore rules need checking.
6. The need says 'increase the number of user'. The Product Owner should say whether this means more app users or more trip members. The screens do not change either way.
7. The Figma file was not opened in this run. These screens still need to be drawn in Figma.
